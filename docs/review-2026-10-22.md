## 3. Permissions: pages that had no check
The automatic check (`App\Traits\Authorizable`) only knows index, show, create, store, edit, update, destroy. Other actions had no check at all, so any signed-in person could open them.
Now gated (`Controller::requirePermissions()` or an explicit check), using the permission the menu already asks for:
- Reports: general, general PDF, check-in, check-out, transfer, adjustment, warehouse stock, warehouse amounts, warehouse check-in, most used material need `read-reports`.
- System Logs (`/activity`) needs `read-activity`.
- Activities screen (whole CRUD, it had `setAbilities([])` and nothing else) needs `create-checkouts`.
- Import / export of Items, Check-ins, Check-outs, Units, Categories (and Contacts import): `read-X` to export, `create-X` to import (the import POSTs too).
- Barcodes page, item stock trail, delete item photo, low-stock preview, per-warehouse alerts page, Supplier Records explorer print / PDF / balances.
Checked with a user who has no permission and no role: pages that answered 200 went from 42 to 13 (all intended: own alerts, terms, contacts list, branch dashboard, launcher search...). Tests: `perm_gates_test` (39).
Left as they are: the contacts list (`read-contacts` is allowed for everybody by design), the lookup endpoints used by forms (search items / contacts, check stock), the package route `attachments/dropzone` (500 on an empty upload).

## 4. Speed
Measured on the live copy of the database as Super Admin (418 pages). Medians and the slowest pages:
- Whole-app: permission checks 2.5 ms -> 0.03 ms each (`app/Traits/FastPermissionChecks.php`, `app/Support/Permissions/TrackedPermissionRegistrar.php`, wired in `AppServiceProvider`). Same answers as Spatie on all 676 permissions (`perm_fast_test`, 16 checks, including role / permission changes).
- Every full page load no longer carries the 245 KB route table: it is a separate cached script `/ziggy.js?v=...` (`App\Support\ZiggyScript`, route `ziggy.script`, `window.route` set in `resources/js/app.js`, cached by the service worker). Login page 330 KB -> 57 KB.
- Weather page 4.7 s / 378 queries -> 0.9 s / 22 queries (batched snapshots, warnings, observations, rules, work).
- Dashboard 1.7 s -> about 0.7 s: indexes on `activity_log` and `notifications` (migration `2026_12_06_100000_add_speed_indexes`), stock value summed in SQL.
- Transfers 1.05 s -> 0.5 s (50 repeated settings queries and permission checks), Company Assets (50 queries removed), report pages: the stock list of every warehouse (about 400 KB) is no longer sent, only of the chosen warehouse, the form fetches another one when it is picked (`reports/warehouse-items/{warehouse}`).
- Four identical prayer message queries and the adhan list per page are read once; the unread alert number is kept for 10 seconds (cleared when alerts are read).
- Deploy: `.cpanel.yml` now also runs `route:cache` and `view:cache` after `optimize:clear` (config is not cached on purpose: 45 places still read `.env` directly). NOTE: if a build is ever put on the server by zip instead of Git, run `route:clear` once, or new pages answer 404 until the route cache is rebuilt.

## 6. Office roles and "All warehouses" (2026-10-22)
- Migration `2026_12_07_100000_roles_all_warehouses_and_office_roles` adds `roles.all_warehouses` and creates **Accounts**, **Chief Accountant**, **Cashier**, **Administration** and **Receptionist** from `App\Support\RoleBlueprints` (a starting guess; change on the Roles screen). Technician already existed (135 permissions) and is untouched. It only adds permissions, never removes, so it is safe to run again.
- Every new role gets the "everyone" set (`RoleBlueprints::EVERYONE`: messages, own tasks / reminders / attendance, notices, weather, QR scan, view-only lookups of warehouses, items, units, categories, contacts).
- "All warehouses" is a tick box on the Role screen: people with that role get every project / warehouse when they are saved or when the box is ticked, and every warehouse created later (`App\Support\AllWarehouseRoles`, hooks in `UserController`, `RoleController`, `Warehouse::booted`). The five roles have it ticked.
- Split of duties: Accounts prepares; Chief Accountant approves / authorises (vouchers, payment requests, supplier invoices, fund allocations, weekly administration, salary, advances, loans) and holds the books; Cashier records payments and pays (vouchers, salary, fund allocations, weekly administration, transport); Administration prepares the weekly administration, travels, staff, compliance, assets, archive; Receptionist handles contacts, gate passes, delivery notes, tasks. Test: `roles_test` (31).
